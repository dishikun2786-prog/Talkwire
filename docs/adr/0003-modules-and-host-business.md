# ADR-0003：可选模块与宿主业务的边界

- 状态：已采纳
- 日期：2026-10-25
- 依据：ADR-0001 第 8、9 条；`docs/modules.md`

## 背景

原版服务端把通话计费、群 AI、红包写死在核心里。Talkwire 要让别的项目只拿聊天，也要让小桃子把这些业务原样接回来。Phase 7、8 做通话客户端、机器人钩子、扫码入群和后台时，需要定下哪些归框架、哪些归宿主。

## 决定

1. **模块**：通话（`call`）、扫码入群（`groupjoin`）、群机器人（`groupai`）、端到端加密（`e2ee`）是可选模块。服务端按 `TALKWIRE_MODULES` 装，宿主按需实现对应接口，客户端按需装对应的包；每一个都能单独装上、单独拿掉，核心产物的依赖树里没有 libsignal 和 RTC SDK。
2. **钱和规则归宿主**：谁能打给谁、RTC 频道与凭证、通话计费、机器人回答什么、红包和转账，全在宿主。IM 只负责把信令、问题和卡片状态送到，并在宿主不答时按配置的兜底文案收场。
3. **机器人钩子是通用接口**：原版的群 AI 问答改成“宿主回答、IM 以助手身份发进群”。助手的名字与兜底文案进运行配置，默认值与原版逐字相同。
4. **业务卡片不进 SDK**：红包、转账等是宿主的自定义消息类型；状态变化走通用的 `custom-broadcast`，原版的 `red-packet-broadcast` 只为迁移保留。
5. **后台**：宿主 SDK 提供后台接口（`talkwireAdminRoutes`），前端是可嵌入的 React 包 `@talkwire/admin`（不另建 `admin-kit/` 目录）。通话记录由宿主在自己的通话处理器外面包一层 `recordingCalls` 得到，只存元数据，不存频道号与 RTC 凭证；计费金额是宿主业务，不在 Talkwire 的记录里。
6. **E2EE 的许可证**：服务端只存转不透明的密文，仍为 Apache-2.0；链接 libsignal 的客户端模块单独发布，AGPLv3。

## 后果

- 宿主要写的东西多了几个可选接口，但每个都有 Node 参考实现与测试；不用的模块不写。
- 记录写失败、宿主计费抛错都不能让通话失败：`recordingCalls` 吞下记录错误并报给 `onError`，结束原因无论计费结果如何都会记下。
- RTC 适配器（7.4）放在 `examples/`，Android 另发一个只按 Maven 坐标依赖 dingrtc 的可选 AAR，核心不依赖任何 RTC SDK。
